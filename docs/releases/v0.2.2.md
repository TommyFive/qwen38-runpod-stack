### Definition of "complete removals"

The paths in the inventories below constitute a **complete, reconciled inventory of intentional file-level v1→v2 B pruning** as implemented in `cpu-audit/prune-candidate.py` and verified against the archived v1 filesystem inventory. The B image was then assembled by copying the pruned filesystem into a scratch-based OCI and splitting it into eight GHCR-compatible layers. Docker/OCI history, layers and config metadata were repacked; this is **not** a byte-identical re-tag of v1.

For the **original upstream Docker Hub image → minimal-v1**, no complete per-file original upstream filesystem manifest was captured. Therefore an exhaustive *physical upstream-to-v2-B path-level diff* is **not supported by evidence**. The full intentional upstream source/build configuration change and every directly specified skipped optional dependency are documented below, but individual packages are **not** incorrectly claimed absent from the final image merely because an extra was not requested. Anyone requiring a complete upstream binary-level filesystem diff would need to extract and compare the exact original upstream and v2 B `linux/amd64` manifests/filesystems on an explicitly resourced x86-64 host; this document does not invent that diff.

## Stage 1 — original upstream image → minimal-v1: build selection, not post-build file deletion

The original SGLang source is pinned to upstream commit `5f55db35e926d50676f75b812640ea2410b0fe0e`; original Dockerfile Git blob `19633581a93a5b18b8513cac71c43ee9454c478f`, original Python pyproject Git blob `0829eac029f7de9b5727ff21526d54996e042bfd`.

The custom build adds **one empty optional dependency group** `qwen38-minimal = []` and builds upstream's `runtime` target with `BUILD_TYPE=qwen38-minimal`, `BRANCH_TYPE=local`. It **does not delete** or modify the project's base `project.dependencies`. Upstream's normal `all` extra instead requests:

- **Diffusion extra:** 20 direct requirement declarations.
- **HTTP/2 extra:** 1 direct declaration (`granian>=2.6.0`).
- **OpenTelemetry tracing extra:** 4 direct declarations.

The **complete 25 upstream optional direct requirement declarations** and their group are preserved in the reproducible inventory [`upstream-all-extra-direct-declarations.tsv`](v0.2.2-removal-inventory/upstream-all-extra-direct-declarations.tsv). The 20 diffusion declarations include media/video/image/diffusers libraries and other optional packages. **This is the complete list of direct optional declarations not requested as `all`; it is NOT a proven package-uninstall list.** Any package also required by the base dependencies or another transitive dependency could remain in the image. The upstream base may have other runtime/source differences, because this v1 image was built as a separately pinned source build rather than produced by subtracting files from the original Hub artifact.

## Layer repacking, binary metadata and optional runtime

The original v1 filesystem was copied from a temporary prune stage into a scratch OCI image; image configuration was separately carried across, with additional experiment labels. The initially too-large single filesystem layer was split into **8 compressed layers** compatible with the GHCR per-blob cap. This rewrites the image's OCI manifests/history and is why the final immutable digest differs, even when application binaries have not been recompiled.

**Historical metadata caveat:** the immutable v2 B digest retains its pre-GPU-test OCI image description labelling it a CPU-only experimental candidate. This label is now **outdated** because RTX PRO 6000 GPU, SGLang NVFP4 + DFlash2, Lean and Full were subsequently tested. A GHCR tag alias does **not** modify embedded OCI labels. This document is the authoritative later runtime acceptance record; fixing the embedded label would require a new OCI config/manifest and a different digest, which has **not** been authorized here.

**OpenWebUI is NOT baked into v2 B**. For `SERVE_WEBUI=1`, the corrected bootstrap supplies pinned, SHA256-checked `uv 0.12.10`, creates an isolated runtime venv and installs OpenWebUI `0.11.4` only on demand. `SERVE_WEBUI=0` skips the installation, caches and listeners entirely. A new release or template must never claim that bootstrap script changes alter the existing immutable Docker image bytes.
