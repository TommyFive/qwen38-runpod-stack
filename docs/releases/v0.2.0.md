## Live validation

- **Run01:** NVIDIA RTX PRO 6000 Blackwell (96 GB), NVFP4 main model + DFlash2, private GHCR pull, authenticated chat completion **PASS**, unauthorized request HTTP 401. Partial-cache first inference healthcheck at **8m39s**. Provider displayed *critical physical host error* and restarted the container; this is **not** a reliable uncontaminated cold-start baseline.
- **Run02:** same GPU class with **20 GiB lean RAM-first container disk**, image successfully pulled, SGLang generated healthchecks. No full standardized 8192/1024 x5 performance result was confirmed at initial release validation.
- Python dependencies ~16.85 GB logical; FlashInfer Cubins and JIT ~6.75 GB logical are potential future optimizations **only after kernel profiling**, not removed in this release.
- Main/draft checkpoints are stored on RAM-backed tmpfs (`/dev/shm`) in default `MODEL_STORAGE=ram` mode, not on the 20 GiB writable SSD.
- **Known limits:** Full OpenWebUI integration and tailnet-only mode specifically *on this new image* need separate end-to-end paid GPU validation, though they are integrated using the previously validated host bootstrap from the v0.1.0 repo. Standardized benchmark and truly uncached cold-start vs original image also remain to be measured. Treat these as limited-rollout release gates, not completed metrics.

## Continuing image optimization

The v0.2.0 **minimal-v1** image is a measured 12.1% smaller than the
official reference, not a final minimum. Future iterations will investigate
`flashinfer_cubin` and `flashinfer_jit_cache` assets, identify kernels
actually used on Blackwell SM120, and test a second smaller image only
after preserving CUDA, DFlash2 and JIT startup functionality. **No
additional size/speed improvement is claimed yet.** See
[layer audit](../../images/sglang-qwen38/OPTIMIZATION_V3.md).

## Templates / launchers

- Four **separate** RunPod templates can be generated; previous templates are not overwritten:
  - `qwen38-v0.2.0-full-public`: Full SGLang + OpenWebUI, RunPod proxy, **20 GiB** RAM-first default.
  - `qwen38-v0.2.0-lean-public`: SGLang-only, RunPod proxy, **20 GiB** RAM-first default.
  - `qwen38-v0.2.0-full-tailnet`: Full, Tailscale-private, **no published ports**, **20 GiB** RAM-first default.
  - `qwen38-v0.2.0-lean-tailnet`: Lean, Tailscale-private, **no published ports**, **20 GiB** RAM-first default.
  - The historical first v0.2.0 deployment used **150 GiB Full** and **20 GiB Lean**. Those original templates were subsequently deleted by the owner; the **current repository defaults** above apply to newly generated templates.
- `qwen38fast` and `qwen38pi` resolve the exact versioned template by name, verify its pinned image ref and intended network mode. For **public GHCR** newly created templates no longer embed a private registry-auth ID; existing private templates remain compatible. For private templates, portlessness is rechecked immediately before GPU Pod creation. Explicit `QWEN38_TEMPLATE*` IDs remain supported as opt-in rollback.
- Versioned template creation uses a two-step RunPod API (small no-secret skeleton, then secrets-as-references ENV update) because the legacy single API call failed with a 500 on a large environment payload. Incomplete templates never launch SGLang without `BOOTSTRAP_B64` and `SGLANG_API_KEY`.
- All RAM-first templates now default to **20 GiB**. Only Custom Lean has been live-tested at 20 GiB; Full/OpenWebUI and official upstream are not yet validated at that size. **Switching to SSD downloads requires increasing the Container Disk or attached SSD storage.** Creating SSD-mode templates or launching with `--storage ssd` defaults to **100 GiB**, and explicit SSD disk settings below 50 GiB are rejected (50 GiB is not a validated recommendation).
- Existing model, DFlash2, authentication, Tailscale helper, storage helper and cold-start trace defaults are preserved from the v0.1.0 integrated baseline.

## User setup / backout

1. The GitHub [image release workflow](../../.github/workflows/qwen38-image-release.yml) succeeded. The GHCR package was subsequently made **Public**, and anonymous retrieval of the exact 31-layer GPU-tested manifest was verified on **2026-10-11** using `python3 images/sglang-qwen38/tools/check-public.py`. Other RunPod accounts now need **no personal GHCR registry credentials**. Existing owner's templates may retain their old registry credentials and remain supported.
2. Install the merged repo scripts using `./setup.sh` (does not launch GPUs). Run `./create-templates.sh`; it creates versioned templates and prints their IDs. It does **not** overwrite previous templates.
3. Then use `qwen38pi` for the tested lean path, or `qwen38fast` for Full (Full GPU validation still pending). To select Tailscale, use `--network tailnet`. Require valid RunPod Secret references, never put real tokens in GitHub files or shared shell commands.
4. To choose the **official upstream** image instead, create a separate `qwen38-official-*` template family with `./create-templates.sh --image official`, then run `qwen38pi --image official` or `qwen38fast --image official`. The official image is publicly available on Docker Hub and needs no private GHCR credential; its Lean and Full templates now default to 20 GiB for RAM-first mode (unvalidated for the official image) and 100 GiB for SSD model downloads. For the existing custom family, use `--image custom` (the default); it remains pinned to the verified digest. Set `QWEN38_IMAGE_VARIANT` to select an image across both commands. Explicit `QWEN38_TEMPLATE*` IDs remain advanced rollback overrides, not the default way to change image families.
5. Stop/delete paid Pods only when no longer needed; creating a template alone does not charge GPU runtime. Never modify a running Pod to switch images.
