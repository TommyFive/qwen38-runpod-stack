Check workflow status; a GitHub Release by itself does **not** prove GHCR's version alias was published.

## Live validation

- **Run01:** NVIDIA RTX PRO 6000 Blackwell (96 GB), NVFP4 main model + DFlash2, private GHCR pull, authenticated chat completion **PASS**, unauthorized request HTTP 401. Partial-cache first inference healthcheck at **8m39s**. Provider displayed *critical physical host error* and restarted the container; this is **not** a reliable uncontaminated cold-start baseline.
- **Run02:** same GPU class with **20 GiB lean RAM-first container disk**, image successfully pulled, SGLang generated healthchecks. No full standardized 8192/1024 x5 performance result was confirmed at initial release validation.
- Python dependencies ~16.85 GB logical; FlashInfer Cubins and JIT ~6.75 GB logical are potential future optimizations **only after kernel profiling**, not removed in this release.
- Main/draft checkpoints are stored on RAM-backed tmpfs (`/dev/shm`) in default `MODEL_STORAGE=ram` mode, not on the 20 GiB writable SSD.
- **Known limits:** Full OpenWebUI integration and tailnet-only mode specifically *on this new image* need separate end-to-end paid GPU validation, though they are integrated using the previously validated host bootstrap from the v0.1.0 repo. Standardized benchmark and truly uncached cold-start vs original image also remain to be measured. Treat these as limited-rollout release gates, not completed metrics.

## Templates / launchers

- Four new **separate** RunPod templates are provisioned; previous templates are not overwritten:
  - `qwen38-v0.2.0-full-public`: full SGLang + OpenWebUI, RunPod proxy, **150 GiB** disk (conservative pending Full validation).
  - `qwen38-v0.2.0-lean-public`: SGLang-only, RunPod proxy, **20 GiB** disk, RAM-first.
  - `qwen38-v0.2.0-full-tailnet`: Full, Tailscale-private, **no published ports**, **150 GiB**.
  - `qwen38-v0.2.0-lean-tailnet`: Lean, Tailscale-private, **no published ports**, **20 GiB**.
- `qwen38fast` and `qwen38pi` resolve the exact versioned template by name, verify its GHCR image ref, registry-auth ID and intended network mode. For private templates, portlessness is rechecked immediately before GPU Pod creation. Explicit `QWEN38_TEMPLATE*` IDs remain supported as opt-in rollback.
- Versioned template creation uses a two-step RunPod API (small no-secret skeleton, then secrets-as-references ENV update) because the legacy single API call failed with a 500 on a large environment payload. Incomplete templates never launch SGLang without `BOOTSTRAP_B64` and `SGLANG_API_KEY`.
- Full retains 150 GiB; Lean defaults to 20 GiB only for RAM-first mode. Explicit SSD checkpoint storage gets a larger safe default (150 GiB).
- Existing model, DFlash2, authentication, Tailscale helper, storage helper and cold-start trace defaults are preserved from the v0.1.0 integrated baseline.

## User setup / backout

1. Ensure the GitHub [image release workflow](../../.github/workflows/qwen38-image-release.yml) succeeded and the GHCR tag exists. Private package must grant the RunPod account **read** access through its preconfigured `ghcr.io` registry entry.
2. Install the merged repo scripts using `./setup.sh` (does not launch GPUs). Run `./create-templates.sh`; it creates versioned templates and prints their IDs. It does **not** overwrite previous templates.
3. Then use `qwen38pi` for the tested lean path, or `qwen38fast` for Full (Full GPU validation still pending). To select Tailscale, use `--network tailnet`. Require valid RunPod Secret references, never put real tokens in GitHub files or shared shell commands.
4. To roll back the **image**, use the previous existing template IDs through explicit `QWEN38_TEMPLATE` and `QWEN38_TEMPLATE_PI` (also `QWEN38_TEMPLATE_TAILNET*` for the private route); or create new templates with `QWEN38_IMAGE_REF=lmsysorg/sglang:dev-qwen38-27b-dflash2`.
5. Stop/delete paid Pods only when no longer needed; creating a template alone does not charge GPU runtime. Never modify a running Pod to switch images.
